# 终端版：2024 年的原版 C 贪吃蛇

`../c-original.c` 是 2024 年写的 Windows 控制台贪吃蛇。它的 AI 是一组单行道规则：每格只开两个出口，再加上"吃完能回到尾巴才吃"的检查。这个文件是本项目的起点之一，一个字都不改。这个目录里的东西，都只是在它外面套一层。

| 文件 | 做什么 |
| --- | --- |
| `record.c` | 录屏和计时用：默认 32×32（`--size` 可改）、穿边，AI 一直开着，不限速，显示每局用时 |
| `original.c` | 在 macOS 和 Linux 上运行原版程序本身（菜单、手动操作、速度调节都在） |
| `compat/` | 原版用到的那几个 Windows 控制台调用的替身：移动光标、设置颜色换成 ANSI 转义码；`kbhit`/`getch` 改成终端原始模式；`clock()` 改成真实时间 |

## 编译和运行

macOS / Linux：

```sh
make                              # 生成 record 和 original
./record                          # 一局，种子 1；按任意键开始，Esc 或 q 退出
./record --games 50               # 连续 50 局，种子 1、2、3……
./record --every                  # 每一步都画（慢很多，瓶颈在终端）
./record --headless --games 5     # 不画，每局一行结果打到 stderr
./original                        # 原版：先按 6 打开 AI，按 4 加速，空格开始
```

画画面时，每局的结果等全部下完再列在棋盘下方，不会打乱画面。其他选项：`--seed N` 指定第一局的种子；`--size N` 换成 N×N 的棋盘（2–64，默认 32）；`--gap S` 每局吃满后停 S 秒；`--now` 不等按键直接开始。终端窗口至少要 64 列、35 行。

Windows（MSVC）：`cl /O2 /std:c17 record.c`；原版直接编译 `..\c-original.c`。

## record.c 怎么跑

- **AI：** 直接调用原版的 `ai()` 和 `shift()`。每一步的走法和原版 `game()` 一样，只是去掉了等待和逐步绘制。
- **画面：** 用原版自己的 `set_brush` 画，配色也是原版的：白底、红蛇、深红蛇头、绿色食物。每帧只重画变了的格子，默认每秒最多 60 帧，`--every` 改成每步都画。
- **食物：** 用和 MSVC `rand()` 相同的公式取随机数，所以同一个种子在任何系统上下的都是同一局。种子 1–5 依次 97,413、91,657、88,836、88,680、96,856 步吃满，和 Windows 上的结果一致。
- **计时：** 每局从第一步算到吃满，包括往终端输出的时间。

## 实测：32×32 一局吃满要多久

| 机器 | 不画 | 每秒 60 帧 | 每步都画 |
| --- | --- | --- | --- |
| Apple M4，clang -O2，macOS | 0.17–0.22 s | 0.17–0.20 s（约 12 帧，伪终端） | 0.61 s（伪终端） |
| Ryzen 7 6800H，MSVC /O2，Windows | 0.43–0.47 s | 0.45–0.49 s（约 30 帧，隐藏控制台） | 13.4 s |

走一步要多久，随棋盘大小变：M4 上 8×8 约 0.25 µs（`./record --headless --size 8 --games 1000`，一局平均 399.5 步），10×10 约 0.35 µs，32×32 约 1.8 µs。

Windows 那一行来自同样调用原版 AI、同样种子的另一个录屏程序，在 Windows 上测的。

macOS 那一行是在伪终端（`script`）里跑的，输出不经过真正的终端窗口绘制，所以是下限。在终端窗口里实际跑，"每秒 60 帧"应该差不多，"每步都画"会慢不少：一局要往终端写约 28 MB 的转义码。

## 还能更快：把棋盘大小写成常数

原版的 `width`、`height`、`size` 是变量（菜单里能改棋盘大小），所以 `shift()` 和 BFS 每看一格都要做几次真正的整数除法和取模。把 `shift`、`bfs`、`ai` 里的它们直接写成 32 和 1024，编译器就能把除法换成移位和按位与。走法不变，种子 1–100 每局的步数和原版完全一样，只是快了将近一倍：

| 机器 | 原版 | 写成常数 | 快了 |
| --- | --- | --- | --- |
| Apple M4，clang -O2 | 0.174 s（1.84 µs/步） | 0.094 s（0.99 µs/步） | 1.9 倍 |
| Ryzen 7 6800H，MSVC /O2 | 0.472 s | 0.202 s | 2.3 倍 |

都是 32×32 不画画面、一局吃满的用时；M4 是种子 1–100 的平均，6800H 那一行来自 Windows 上的测试。这个目录和视频都用一字未改的原版，这里只记下结果；想自己试，把 `../c-original.c` 复制一份再替换。

## 视频里的实录

《退路》引子右边的终端，是 `record --now --games 130` 在 64×36 伪终端里的真实输出，连同时间戳一起录下，再由视频渲染器逐帧回放。录的工具是这个目录里的 `capture-term.py`（在仓库根目录运行）：

```sh
python3 c/terminal/capture-term.py record.cast -- c/terminal/record --now --games 130
```

录像是 asciinema v2 格式，也可以直接用 `asciinema play record.cast` 播放。视频用的那一份（20 MB，没有放进仓库）前 20 秒吃满 111 局，平均每局 0.18 秒。
