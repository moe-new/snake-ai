# 贪吃蛇算法对照

九项策略共用一个有墙贪吃蛇环境，主要比较吃满所需步数，计算耗时只作参考。游戏、批测和终端汇总全部用 C11 实现，无 Python、Node 或第三方运行时依赖。

## 算法与实测

10×10、30×30 各测试种子 1–100，每种子一次，每项先热身一局。平均步数和参考耗时仅统计吃满局。

| 算法 | 核心策略 | 10×10 平均步数 | 30×30 平均步数 | 30×30 参考耗时 ms／局 |
|---|---|---:|---:|---:|
| 固定回路 | 沿固定满盘环逐格走 | 2462.05 | 202532.31 | 5.91 |
| 单行道 BFS＋追尾 | 找食物、试吃查尾路，必要时追尾 | 1319.67 | 91447.04 | 218.89 |
| 步步为营 | 完整路径与吃后的回路退路证书 | 1245.47 | 90926.39 | 156.77 |
| 局部动态回路 | 局部四边交换，保持单环并缩短路线 | 1286.38 | 79030.53 | 23.12 |
| BFS＋可达性保护 | 额外检查吃后空地是否被隔断 | 1038.48 | 50192.39 | 451.34 |
| 加权 Cell＋安全尾段裁剪 | 加权细胞树搜索与安全尾段释放 | 990.34 | 46415.42 | 572.36 |
| twanvl PHC | 固定环序上的扰动捷径 | 1616.62 | 103795.98 | 4.77 |
| twanvl DHCR | A* 引导的闭环修复 | 1244.97 | 60317.48 | 416.72 |
| twanvl 加权 Cell | 上游加权细胞树基线，不裁尾 | 1029.91 | 47437.91 | 577.79 |

前三项是原有算法参照，4–6 是补充实验，后三项是 twanvl 来源对照。加权 Cell＋安全尾段裁剪基于 twanvl 的移植与改进，不是原创细胞树算法。

吃满情况：twanvl DHCR 在 10×10 为 97/100、30×30 为 99/100，其余八项均为 100/100。四个未吃满样本均触发连续 8N 步无增长预算；预算停止不证明永久死循环。

参考耗时来自 AMD Ryzen 7 6800H、MSVC 19.42.34435、Release /O2 的一次串行采样，包含初始化、算法、身体推进、苹果采样和轨迹摘要，排除输出和独立验证。单次采样不用于证明微小速度差异。

31×31 仅做前 10 个种子的兼容性抽测：步步为营 10/10 吃满，原单行道和可达性保护均未吃满，其他策略标 N/A。奇数格四邻接棋盘没有满盘简单环；旧单行道奇数图还存在无出口角落，不能据此断言 BFS 原理不适用于奇数棋盘。

## 环境与算法约束

- 初始身体 [1,0]、向右、长 2；每颗苹果增长一格。不增长时可进入同时离开的尾格。
- 苹果使用 xorshift32、行优先空格列表取余采样。同种子共享随机流，身体不同意味着苹果坐标可能不同。
- 单局最多 2,000,000 步；连续 8N 步未增长记预算停止。
- 1–6、9 使用各自单行道／格子图，7–8 保留来源的四向选步。Cell 用 2×2 格子树约束搜索，普通 Cell 的启发式可达性检查不等于完整回路证书。
- 安全裁尾只放宽搜索视图：长 L、头到尾编号 i 的旧身体格在吃到当前苹果前于第 L−i 步释放；仅忽略曼哈顿距离不小于释放时刻的连续尾段。碰撞、增长和苹果采样仍使用完整身体。

主要决策成本：固定回路与 PHC 为 O(1)；BFS／队列模拟可达性保护 O(N)；局部改环候选有界，接受后 O(N) 重建环序；步步为营证书 O(N α(N))；Cell／DHCR 堆搜索 O(N log N)，DHCR 修复扫描 O(N)。公共身体推进 O(L)、生成苹果 O(N) 均计入参考耗时。

## 构建与运行

从源码构建需要 CMake 3.20+ 和 C 编译器；运行已有二进制不需要构建工具。

    cmake -S . -B build
    cmake --build build --config Release
    ctest --test-dir build -C Release --output-on-failure

    .\snake-compare.exe --bench
    .\snake-compare.exe --bench --games 1
    .\snake-compare.exe --list
    .\snake-compare.exe --algorithm local-cycle --width 30 --height 30 --seed 1 --games 1

--bench 默认执行上述完整采样，--games 1 可快速试跑。结果只打印到终端，不创建数据文件，也不自动修改本文。--verify 启用逐步身体检查，--trace 在单局终端结果中附加轨迹摘要。

macOS／Linux 使用 ./snake-compare。二进制输出在本目录，build/ 是可重新生成的构建文件。

## 来源与适配

单行道和步步为营分别对应本仓库 [c-directed.js](../../web/engine/c-directed.js)、[tiled-directed.js](../../web/engine/tiled-directed.js)；局部动态与可达性保护是项目补充实验。

twanvl 对照锁定 [ee180ede](https://github.com/twanvl/snake/tree/ee180ede14ea15cc83d5e469de00404bd6c8e98b)。PHC 引用 John Tapsell 思路；DHCR 是 twanvl 对 AlphaPhoenix 的简化重实现，不等同于作者完整两阶段修复。

来源坐标上下反射以适配共同初始身体；堆的平局顺序固定为原 MSVC 行为，其他原生 C++ 标准库可能有不同平局顺序。DHCR 对源码未定义的“食物无路”输入增加沿旧环回退；上述采样未触发。Cell 对无路径缓存和无效绕路目标也增加了边界保护。许可与署名见 [NOTICES.txt](NOTICES.txt)。
